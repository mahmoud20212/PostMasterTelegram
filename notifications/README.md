# إشعارات OnePost والعمل والراحة

الإشعارات مفعّلة دائمًا للأحداث المهمة: دخول الراحة وانتهاؤها، بداية انتظار
Telegram وانتهاؤه، تقييد الحساب أو انتهاء الجلسة، الحد اليومي، وتفعيل الباقات
وتغييرها وتجديدها وانتهاؤها. Slow Mode يصدر تنبيهًا مجمّعًا واحدًا لكل مستخدم
خلال 30 دقيقة. لا يوجد إشعار لكل رسالة أو لكل فشل مجموعة.

## السلوك

- يُختار أول حساب مربوط بنجاح كحساب نشر، وتبقى الاختيارات اليدوية عند ربط حسابات أخرى.
- تفعيل السكون أثناء النشر يبدأ فترة عمل كاملة، ثم راحة، وتتكرر الدورتان.
- إذا كان النشر متوقفًا، يبدأ العدّ عند تشغيله. كل تشغيل يدوي جديد يعيد فترة العمل.
- تُحفظ ساعات العمل والراحة معًا بعد إدخال القيمتين، من 1 إلى 24 لكل منهما.
  حفظهما يبدأ فترة عمل جديدة حتى لو كانت هناك راحة جارية.
- الوقت المنقضي يشمل الفواصل وراحة الباقة وقيود Telegram وانقطاع العمليات.
  إعادة تشغيل العمليات لا تعيد العدّ، ولا تسبب استدراك رسائل أو إشعارات قديمة.
- انتهاء الراحة يستأنف الجدولة من المؤشر المحفوظ مع مراعاة القيود الأخرى.
  الطلب الجاري بالفعل قد يكتمل بعد بداية الراحة؛ الطلب الذي لم يبدأ يؤجَّل.
- التوقيت يُحفظ كوقت واعٍ بالمنطقة الزمنية، وتُعرض المواعيد بمنطقة المستخدم
  المحفوظة، مع Asia/Gaza كبديل عند وجود قيمة غير صالحة.

## التسليم

`BotNotification` سجل أحداث وصندوق إرسال دائم. يُحفظ الحدث داخل معاملة تغيير
الحالة بمفتاح فريد. المجدول الحالي ينشر مهمة محدودة لكل إشعار على طابور
`notifications`. لا يُرسل إشعار داخل معاملة النشر أو الاشتراك.

يحافظ صندوق الإرسال على حد للمهام المعلقة وعلى إشعار واحد جارٍ لكل مستخدم.
فشل نشر المهمة إلى Redis يُستعاد بعد انتهاء رمزها. إعادة التسليم لا ترسل الحدث
نفسه مرتين. تنبيهات مراحل السكون القديمة تُلغى عند تغير المرحلة أو توقف التشغيل.

عند `RetryAfter` يُحفظ موعد المحاولة التالية دون انتظار داخل العامل، بحد أقصى
ثلاث محاولات تسليم. حظر البوت أو رفض الطلب نهائي. عند مهلة أو فقدان رد قد يخفي
قبول Telegram، تصبح النتيجة `unknown` ولا يُعاد الإشعار؛ قد يفوت تنبيه بدل
تكراره. يسري ذلك أيضًا على فقدان العامل بعد علامة الإرسال. فشل التنبيه لا يوقف
نشر المستخدم. يمكن مراجعة السجل من لوحة الإدارة.

## التحديث والتشغيل

لم تُطبَّق هذه الترحيلات تلقائيًا على قاعدة المستخدمين. بعد نسخ القاعدة والمفتاح
احتياطيًا، أوقف نسخ البوت والعامل والمجدول القديمة قبل التحديث. لا تغيّر مفتاح
تشفير الجلسات، ولا تنقل البيانات بين SQLite وPostgreSQL ضمن هذا التحديث.

الترحيلات الجديدة: publishing/0009 لحالة العمل والراحة، notifications/0001
للإشعارات، وtelegram_accounts/0005 لاختيار الحساب الافتراضي ومنع الاختيار المزدوج.
الترحيل الأخير يحافظ على الاختيار الحالي، أو يختار أقدم حساب متصل له جلسة.
إن وجد أكثر من اختيار سابق للمستخدم، يتوقف برسالة واضحة دون حذف الحسابات.
النشر الجاري مع سكون مفعّل يبدأ فترة عمل كاملة عند أول فحص بعد التحديث.

```powershell
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\celery.exe -A config worker -l INFO --pool=threads --concurrency=4 --prefetch-multiplier=1 -Q publishing,notifications,celery
.\.venv\Scripts\python.exe manage.py run_publishing_scheduler
.\.venv\Scripts\celery.exe -A config beat -l INFO
.\.venv\Scripts\python.exe -m bot.main
```

شغّل العمليات الطويلة في نوافذ منفصلة. يستمر Beat في انتهاء الاشتراكات، أو
يمكنه تشغيل المجدول الموجود عند تفعيل PUBLISHING_USE_BEAT. في الإنتاج استخدم
PostgreSQL واتصالًا مباشرًا أو session pooling، وLinux prefork بدل threads.

```powershell
.\.venv\Scripts\python.exe -B manage.py test publishing notifications telegram_accounts subscriptions.tests users.tests messages.tests telegram_groups.tests --settings=config.settings.testing --noinput
```

الاختبارات تستخدم محاكاة Telegram وقواعد مؤقتة. لا توجد رسائل حقيقية ضمنها.
للتأكد من التزامن في PostgreSQL، استخدم ONEPOST_TEST_DATABASE_URL؛ تنشئ إعدادات
الاختبار قاعدة منفصلة باسم عشوائي ولا تستخدم بيانات التطبيق. قواعد الاشتراكات
الحالية وسياسة نتائج النشر unknown وتعطيل typing تبقى كما هي. لم تُقَس سعة
المستخدمين تحت حمل فعلي.
